## 1. 资源采样（只读脚本）

在 Windows PowerShell 5.1 中从仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Collect-ResourceBaseline.ps1 -DurationSeconds 600 -IntervalSeconds 2 -OutputDirectory .\baseline-results
```

产生的 CSV 记录 PID 级 CPU 机器占比、工作集、Private Bytes、句柄及线程数量，metadata 文件记录采样环境。程序包含运行在相同映像名下的监控子进程，因此记录每个 PID 而非只取一个进程。**不修改硬件、不提权、不启动/终止 OSH**。采样期间按场景运行 OSH；脚本只识别当前存在的进程。

注意：CPU 首个样本为空是正常的；`not-running` 表示当前未发现进程；CSV 不测量 UI P95 响应，也不能区分硬件监控子进程和主程序的启动参数，需要在必要时额外记录命令行。系统内核、PawnIO、SYSTEM 进程消耗不能按该 CSV 直接归因给 OSH。

建议先采四种状态：OSH 未运行、OSH 运行且监控默认、OSH 运行且高刷新、OSH 运行且浮窗关闭/打开。独立观察 Windows 任务管理器里的 System CPU 和相关驱动行为。文件包含机型信息，公开前先审查和脱敏。

## 3. 验收口径

- 原始温度样本、平滑/显示温度及参考工具需区分，严禁「无效＝0°C」「未知＝40°C」混入有效温度。
- 跟踪**最高温度、持续温度、升温时风扇响应延迟、降温段转速摆动**，不是只看一个瞬时温度。
- 无参考记录时不能对“温度更准/更凉/性能更好”做结论；无目标转速内部日志时明确标为“未采集”。
- 对异常保留发生时刻、操作步骤、OSH 日志、BIOS/驱动和相关设置，先确认可复现再改风控参数。
- 先完成 S0 基线，S1 中的风扇软件调度改动必须单独 PR 和实机 UAT 才能合并。
