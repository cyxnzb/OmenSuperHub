## 1. 温度来源与数值正确性（优先）

| 场景 | 对比/观察点 | 结果 |
|---|---|---|
| 冷启动 | 程序无数据时不展示伪造 40/50°C；随后能正常显示真实温度 | 未测 |
| CPU 空闲 | OSH CPU 温度 vs 参考工具 **同名** CPU Package / AMD Tctl/Tdie；不要拿 CCD 与 Package 直接比较 | 未测 |
| CPU 轻/中负载 | 原始值、平滑显示及参考值同一时刻对照；记录突变和持续偏差 | 未测 |
| 独显唤醒 | OSH 的 GPU Core 对齐 HWiNFO NVIDIA GPU Core，而非 AMD iGPU | 未测 |
| 独显休眠 | 已检测到 NVIDIA dGPU 时只采集 NVIDIA GPU Core；休眠/缺样本则显示不可用，不得回退为 AMD 核显温度 | 未测 |
| 监控进程退出后恢复 | 记录时间、来源日志与温度数据恢复，不出现混杂旧进程数据 | 未测 |
| 屏幕显示/本地导出 | 无效读数不显示为正常温度；`cpu_temp.txt`/`gpu_temp.txt` 不可用时为整数 `-1` | 未测 |
| 挂钟自动校时 | 不应将未来/过期的样本判断为新鲜，观察日志恢复 | 未测 |

主进程日志中查看 `HardwareMonitor [HWMonitor ERR] CPU temperature source:`、`GPU temperature source:`、监控启动失败与失联日志。这些来源日志不等于“传感器物理准确”，需要和参考软件同名指标比较。切换“原始/平滑”显示不能改变底层原始温度采样值。

## 2. 风扇调度与安全性（优先）

| 场景 | 对比/观察点 | 结果 |
|---|---|---|
| 空闲 ≥ 10 分钟 | 不频繁出现大幅上下来回跳转；记录 RPM 与温度时间序列 | 未测 |
| 短暂 CPU 负载/恢复 | 升温时可靠响应，高温不得为“安静”被刻意限速；降温阶段有合理缓降 | 未测 |
| 短暂 GPU 负载/恢复 | NVIDIA 独显与 CPU 热源均正确影响风控（如果当前平台/设置支持） | 未测 |
| RPM 显示开/关 | 温度和负载一致时，切换 `MonitorFan` 不应改变自动控制算法的升降速节奏 | 未测 |
| AUTO → MAX → AUTO | 切换后不沿用旧 AUTO 命令基线，不出现意外低速 | 未测 |
| AUTO → 固定 → AUTO | 观察目标与实测 RPM 和启动后第一条指令的恢复 | 未测 |
| 监控停止/异常退出 | 失去温度时不能假温度控扇；已有安全兜底是否启动及恢复 | 未测 |
| 睡眠→恢复/AC 插拔 | 风控归属、传感器恢复、BIOS/WMI 时延及温度峰值 | 未测 |

注意：`Automatic fan control callback took ...ms` 表示 BIOS/WMI 回调慢，需记录发生频率和当时负载。显示的实际风扇 RPM 与请求目标可能有机械延迟，这**不是**本身的 Bug；持续不响应才需要诊断。

## 4. 立即停止测试 / 回退标准

若发生持续升温且风扇没有响应、异常低速、传感器来源明显选错、程序退出后遗留控制、BIOS 失败反复刷屏、系统长时间高占用或无法恢复默认风扇模式，**立即停止负载，恢复已知可靠的原版控制并保存日志**。不在未经确认的温度来源上执行极限压力测试。

## 5. 反馈格式和放行门槛
